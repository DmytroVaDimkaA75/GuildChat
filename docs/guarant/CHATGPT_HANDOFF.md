# Переказ саме цього чату

## Суть розмови

Користувач разом з асистентом формалізує логіку гаранта Великих споруд (ВС) у Forge of Empires: аналіз JSON-станів, рейтинг вкладників, вартість місць, потрібні внески, стан після внеску та відображення на екранах «Гаранти» і «Мої ВС».

На початку користувач установив режим: перед новим JSON читати наявні правила; спочатку лише аналізувати; завжди показувати всі вартості місць, розрахунок, наступну дію і симуляцію після неї; нічого не фіксувати до явного підтвердження. Якщо користувач виправляє висновок, його виправлення має найвищий пріоритет. Після підтвердження кейс додається до документації, а нове правило створюється лише тоді, коли воно справді було сформульоване й підтверджене.

Користувач попросив створити `STATUSES.md` для окремої фіксації текстів, кольорів плашок і видимості ВС.

## Що було розглянуто

### G-001 — пропорційний внесок

ВС 59-го рівня: власник PASSAT B6 вклав `748 СО`, залишок `2105`; місця коштують `1520`, `760`, `250`, `57`, `10`. Попередній `lastScan` користувач наказав не аналізувати. Сума місць `2597` перевищує залишок, тому після резерву `1 СО` власнику пропорційний внесок на перше місце:

`ceil(2104 × 1520 / 2597) = 1232 СО`.

Це стало R-001. Пізніше встановили, що фактичний коефіцієнт `1232/760 = 1,621052…`, отже достатньо Арки 42 із бонусом 63%. Рівні Арки 1–180 вирішили зберігати в локальному статичному конфігу без регулярного API-оновлення; рівень визначати за точним внеском, а не округленим коефіцієнтом (R-009).

### G-002 — дороге перебиття стороннього

Перші три місця зайняті співгільдійцями; четверте займає сторонній Tertiadecima з `56 СО` при вартості `48`; п'яте — сторонній Джеминист із `48 СО` при вартості `10`; залишок `134`.

Спочатку розглядали безпечне перебиття четвертого за `95 СО` і дозвіл власника. Пізніше користувач відхилив це як надто дороге. Остаточне правило R-007: якщо безпечний внесок більший за вартість місця, перебиття не пропонувати, дозволу не запитувати, місце пропустити. G-002 було переглянуто, рекомендацію `95 СО` скасовано.

### G-003 — неперебивне перше, гарантоване друге

Strannik888 має `1539 СО` на першому місці; залишок `1285`, тому для перебиття бракує (`1540 > 1285`). Друге місце вільне й коштує `810`. Після внеску `810` залишиться `475`, а нижній сторонній з `11` зможе набрати максимум `486 < 810`. Отже друге місце гарантоване. Це R-003.

### G-004 — прикриття четвертого місця

trupis19 має `60 СО` на четвертому, залишок `84`. Власник має вкласти `24 СО`. Користувач наголосив: першочергово прикрити цього вкладника; у «Гарантах» ВС не показувати, у «Мої ВС» червона плашка «Терміново вкласти 24 СО». Примітка: проінформувати власника про необхідність прикрити вклад без гаранту. Це R-004.

### G-005 — недоплата Berd 222

Berd 222 має `594 СО` на другому місці вартістю `610`, тому доплачує `16`. У «Гарантах» ВС бачить лише Berd 222 із червоною плашкою «Вартість місця 2 складає 610 СО. Треба докинути 16 СО». У «Мої ВС» помаранчева: «Очікуємо доплати від Berd 222». Нижчі місця не обробляти до доплати. Це R-005.

### Наступні підтверджені кейси

- G-006: верхні сторонні місця недоступні; власник вкладає `598 СО` для гаранту вільного 3-го, потім вкладник `830 СО`.
- G-007: власник вкладає `63 СО`, захищаючи trupis19 на 4-му; 5-те не включати.
- G-008: повністю порожній розподіл; 1-ше вже гарантоване для внеску `1900 СО`, власник не діє.
- G-009: асистент спочатку хотів прикривати 2-ге, але користувач виправив: для кількох проблемних співгільдійців поспіль прикривати останнього, щоб одразу захистити всю групу. Тут власник вкладає `1952 СО` для 3-го, захищаючи 2–3.
- G-010: та сама логіка для групи 2–5; власник вкладає `2599 СО` для 5-го.
- G-011: 1-ше стороннє неперебивне, 2-ге гарантоване для `900 СО`.
- G-012: порожнє 1-ше з нижнім стороннім; власник `1778 СО`, потім вкладник `2240 СО`.
- G-013: порожнє 1-ше без сторонніх; власник `1821 СО`, потім вкладник `2240 СО`.
- G-014: великий гарант; власник `18377 СО`, потім вкладник `6560 СО`.

Звідси R-006: гарант власника для вільного місця `max(0, C + R − 2P)`, де `P` — вартість місця, `C` — найближчий нижній сторонній внесок або 0, `R` — залишок.

### Пакетний файл `11.json`

Користувач надав повний файл ВС гільдії, щоб відбирати лише неоднозначні. Під час розбору встановлено:

- не перебивати місце, якщо це дорожче за його вартість, незалежно від того, новий це вкладник чи наявний;
- проблеми обробляти суворо згори вниз;
- якщо повна доплата неможлива, пропонувати максимум `залишок − 1`, резервуючи власнику `1 СО`;
- записи з відсутнім, `null` або порожнім `{}` `guarant` повністю пропускати.

Підтверджено:

- G-015: дорогі сторонні 1–2 пропускаються; власник вкладає `16706 СО`, захищаючи співгільдійця на 3-му.
- G-016: Volodimir Prihodko має `1043/2040`; повна недоплата `997`, залишок `371`; рекомендується `370`, резерв власнику `1`, невідновна недоплата `627`.
- G-017: кілька недоплат суворо згори вниз: спочатку `174`, після нового скану `1021`, резерв `1` власнику.
- G-018: після пропуску всіх недоступних позицій дії немає — `no_action_required`, у «Гарантах» не показувати.
- G-019: відсутній/`null`/`{}` `guarant` — повний пропуск без статусу.

## Поточний етап: точна UI-логіка кожного кейсу

Користувач вирішив пройти всі підтверджені кейси та для кожного точно визначити поведінку застосунку.

### UI G-001 — уже підтверджено

«Гаранти»:

- бачать користувачі з Аркою 42+;
- червона плашка «Перелив. Необхідно вкласти 1232 СО»;
- показувати 1-ше місце, `1232 СО`, коефіцієнт `×1,63`.

Коефіцієнт у UI округлювати вгору: до `1,9` включно — 2 знаки, понад `1,9` — 3 знаки. Арку визначати за точним значенням.

«Мої ВС»:

- червона плашка «Перелив. Очікуємо вкладника з пропорційним внеском (1232 СО)»;
- власника окремо не попереджати;
- стан називати гарантованим, хоча плашка червона через терміновість.

### UI G-002 — уже підтверджено

В оригінальному стані 4-те і 5-те зайняті сторонніми, доступної дії немає:

- у «Гарантах» не показувати нікому;
- у «Мої ВС» зелена плашка «Готова до закриття»;
- власник може закривати рівень залишком `134 СО`.

Окремо розглянуто варіант, де 4-те економічно недоступне, але 5-те порожнє й коштує `10`:

- 4-те пропустити;
- власник вкладає `114 СО` для гаранту 5-го;
- до внеску у «Гарантах» не показувати;
- у «Мої ВС» помаранчева плашка «Очікування гаранту. Вкладіть 114 СО для гаранту на 5-те місце»;
- після внеску залишається `20`, 5-те гарантоване для вкладника на `10 СО`;
- після нового скану показувати в «Гарантах», у «Мої ВС» зелену «Гарантоване».

Це новіше формулювання «Очікування гаранту…» замінює старе «Терміново вкласти…» для станів, де власник лише готує вільне місце.

## Точка, на якій зупинилися

Зараз розглядається UI кейсу G-003.

| Місце | Вартість | Вкладник | Внесок |
|---|---:|---|---:|
| 1 | 1620 СО | Strannik888, сторонній | 1539 СО |
| 2 | 810 СО | вільне | — |
| 3 | 270 СО | вільне | — |
| 4 | 67 СО | вільне | — |
| 5 | 10 СО | Tertiadecima, сторонній | 11 СО |

Власник вклав `650`, залишок `1285`. Перше неперебивне; друге гарантоване для внеску `810 СО`. Через повний коефіцієнт `×2` потрібна Арка 180+.

Асистент запропонував, але користувач ще не підтвердив:

- «Гаранти»: Арка 180+, зелена «Гарантоване», показати 2-ге місце, `810 СО`, `×2`;
- «Мої ВС»: зелена «Гарантоване», без попередження власнику.

Продовжувати треба з підтвердження або виправлення саме цього UI для G-003.

## Що ще слід пройти

Після G-003 залишилося уточнити UI кейсів G-004–G-019: кому видно ВС у «Гарантах», фільтр Арки, колір і точний текст плашки, цільове місце, суму й коефіцієнт; що бачить власник у «Мої ВС»; як називається стан; що показується після дії та нового скану.

Черга: G-004 (`24 СО`), G-005 (доплата `16`), G-006 (`598 → 830`), G-007 (`63`), G-008 (`1900`), G-009 (`1952`, група 2–3), G-010 (`2599`, група 2–5), G-011 (`900`), G-012 (`1778 → 2240`), G-013 (`1821 → 2240`), G-014 (`18377 → 6560`), G-015 (`16706`), G-016 (`370`, резерв 1), G-017 (кілька недоплат), G-018 (`no_action_required`) і G-019 (повний пропуск).
