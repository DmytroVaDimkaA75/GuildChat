# Статуси гаранта

Це технічний словник статусів, наявних у поточній реалізації. Наявність статусу в коді не означає, що відповідне бізнес-правило вже підтверджене. Підтверджені статуси містять посилання на правило або кейс.

| Статус | Значення | Типова дія | Підтвердження |
|---|---|---|---|
| `secured_guild_member` | Місце учасника гільдії захищене | Дія не потрібна | лише оголошений у коді |
| `guild_member_can_be_overtaken` | Учасника гільдії ще можна обійти | Проінформувати власника про необхідність прикрити вклад без гаранту | R-004, G-004 |
| `guild_member_below_place_cost` | Учасник гільдії не доплатив повну вартість свого місця | Докидання конкретного учасника до повної вартості | R-005, G-005 |
| `outsider_can_be_overtaken` | Учасник гільдії може обійти стороннього вкладника | Докидання конкретного учасника | лише реалізація |
| `outsider_cannot_be_overtaken` | Стороннього вкладника вже неможливо обійти | Пропустити та перевірити наступне найвище вільне місце | R-003, G-003 |
| `outsider_without_guild_challenger` | Є сторонній вкладник, але немає кандидата від гільдії | Отримати дозвіл власника перебити; після дозволу рекомендувати новому учаснику кінцевий безпечний внесок | R-002, G-002 |
| `empty_guaranteed` | Порожнє місце вже можна безпечно зайняти | Внесок повної вартості місця | R-003, G-003; підтверджено для відображення |
| `empty_requires_owner_guarantee` | Перед зайняттям порожнього місця потрібен гарант власника | Внесок власника | R-006, G-006 |
| `empty_urgent_deposit` | Порожнє місце потребує термінового внеску | Внесок учасника гільдії | лише реалізація |
| `empty_urgent_proportional_deposit` | На всі порожні місця СО не вистачає; поточне місце отримує пропорційну частку | Пропорційний внесок учасника гільдії | R-001, G-001 |
| `empty_owner_confirmation_required` | Для останнього кроку потрібне підтвердження власника | Підтвердження/внесок власника | лише реалізація |
| `no_action_required` | Алгоритм не знайшов дії, яку треба виконати | Нічого не робити | лише реалізація |
| `api_error` | API повернув помилку або непридатну відповідь | Повторити отримання даних/показати помилку | лише оголошений у коді |
| `invalid_data` | Вхідні дані не пройшли перевірку | Виправити або повторно отримати дані | лише оголошений у коді |

Статус після будь-якого внеску визначається новим повним розрахунком, а не переноситься з попереднього стану.

## Дозвіл власника для `outsider_without_guild_challenger`

Примітка для інтерфейсу: **«Отримати дозвіл власника перебити»**.

- Якщо власник дозволив перебиття, відображати Велику споруду на екрані **«Гаранти»**.
- Якщо власник заборонив перебиття, не відображати Велику споруду на екрані **«Гаранти»**.
- До отримання рішення власника не трактувати перебиття як автоматично дозволене.

## Відображення `empty_guaranteed`

Якщо найвище доступне вільне місце забезпечене гарантом:

- на екрані **«Мої ВС»** показувати зелену плашку **«Гарантоване»**;
- відображати цю Велику споруду на екрані **«Гаранти»**;
- на екрані **«Гаранти»** показувати таку саму зелену плашку **«Гарантоване»**.

Назва, колір і значення плашки мають бути однаковими на обох екранах.

## Відображення `guild_member_can_be_overtaken`

Примітка: **«Проінформувати власника про необхідність прикрити вклад без гаранту»**.

- На екрані **«Мої ВС»** показувати червону плашку **«Терміново вкласти N СО»**, де `N` — розрахований внесок власника для захисту першого проблемного місця.
- На екрані **«Гаранти»** таку Велику споруду не відображати.
- Рекомендація стосується лише першого проблемного місця і не включає внески для наступних місць.

## Відображення `guild_member_below_place_cost`

- У **«Гарантах»** відображати ВС лише конкретному вкладнику, який повинен докинути СО.
- У **«Гарантах»** показувати червону плашку: **«Вартість місця N складає X СО. Треба докинути Y СО»**.
- У **«Мої ВС»** показувати помаранчеву плашку: **«Очікуємо доплати від <ім’я вкладника>»**.
- До доплати не показувати рекомендацію для нижчих проблемних місць.

## Відображення `empty_requires_owner_guarantee`

- У **«Мої ВС»** показувати плашку **«Терміново вкласти N СО»**, де `N` — розрахований гарант власника.
- У **«Гарантах»** таку ВС не відображати до внеску власника.
- Після внеску власника й отримання `empty_guaranteed` показувати в «Мої ВС» та «Гарантах» зелену плашку **«Гарантоване»**.
