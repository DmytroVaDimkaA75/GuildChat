# Алгоритм гаранта

Документ описує підтверджену частину алгоритму. Непідтверджені гілки реалізації не вважаються бізнес-правилами.

## Попередня фільтрація записів

1. Перед аналізом перевірити поле `guarant`.
2. Якщо поле відсутнє, дорівнює `null` або є порожнім об’єктом `{}`, повністю пропустити запис за R-008.
3. Не створювати для пропущеного запису штучний статус і не включати його до списку неоднозначних або доступних гарантів.

## Визначення мінімального рівня Арки

1. Після розрахунку нового внеску учасника гільдії взяти номінальну нагороду цільового місця та рекомендовану суму.
2. У статичному локальному конфігу рівнів Арки 1–180 знайти перший `contribution_boost`, для якого `nominalCost × (100 + contributionBoost) ≥ recommendedDeposit × 100`.
3. Записати знайдений рівень у `requiredArcLevel`; зовнішній API під час production-розрахунку не викликати.
4. Якщо внесок не перевищує номінальну нагороду, використати рівень `0`.
5. Для дій власника та адресної доплати наявного вкладника не застосовувати фільтр Арки до видимості необхідної дії.
6. Для нового внеску записати точний `effectiveCoefficient = recommendedDeposit / nominalCost` і відповідний `requiredContributionBoost`; не округлювати коефіцієнт для пошуку рівня Арки.

## Обробка повністю порожнього хвоста

1. Відокремити власника ВС від кандидатів на гарантовані місця.
2. Визначити перше порожнє цільове місце.
3. Перевірити, що всі наступні місця також порожні.
4. Обчислити суму вартостей порожніх місць.
5. Якщо ця сума більша за залишок СО, застосувати R-001:
   - порахувати кількість місць вартістю `1 СО`;
   - обчислити `пропорційний пул = залишок − 1 − кількість місць по 1 СО`;
   - обчислити суму ваг місць із вартістю понад `1 СО`;
   - для поточного місця рекомендувати округлену вгору пропорційну частку;
   - повернути `empty_urgent_proportional_deposit`.
6. Після виконання рекомендації повністю перерахувати залишок, розподіл місць, рейтинг і наступну дію.

Інші гілки алгоритму мають бути описані після підтвердження відповідних правил або кейсів.

## Сторонній вкладник без претендента від гільдії

1. Знайти перше цільове місце зі стороннім вкладником, нижче якого немає учасника гільдії для докидання.
2. Отримати дозвіл власника ВС на перебиття.
3. Якщо дозвіл надано, обчислити кінцевий внесок за R-002:

   `max(внесок стороннього + 1, ceil((внесок стороннього + залишок) / 2))`

4. До запиту дозволу перевірити R-007: кінцевий внесок не повинен перевищувати вартість цільового місця.
5. Якщо внесок перевищує вартість місця, пропустити економічно недоступне місце та продовжити пошук без запиту дозволу власника.
6. Перевірити, що рекомендований внесок не перевищує доступний залишок.
7. Після внеску перерахувати рейтинг і переконатися, що сторонній вкладник не може повернути цільове місце, використавши весь новий залишок.
8. Якщо власник заборонив перебиття, не показувати цю ВС на екрані «Гаранти».

Якщо нижче стороннього вкладника вже є учасник гільдії з внеском `M`, для внеску стороннього `O` та залишку `R` безпечна доплата становить:

`max(O + 1 − M, ceil((O + R − M) / 2))`

Після доплати кінцевий внесок учасника також має пройти обмеження R-007.

## Неперебивний сторонній вкладник

1. Для стороннього вкладника без претендента від гільдії обчислити внесок за R-002.
2. Якщо внесок перевищує залишок ВС, не повертати неможливу рекомендацію.
3. Якщо внесок перевищує вартість місця, не повертати економічно недоцільну рекомендацію за R-007.
4. Позначити позицію як неперебивну або економічно недоступну та продовжити пошук першого наступного проблемного або вільного місця.
5. Для найвищого вільного місця виконати звичайну перевірку гаранту.
6. Якщо гарант власника не потрібен, повернути `empty_guaranteed` із повною вартістю цього місця.
7. Якщо наступне вільне місце дорожче за доступний залишок і до нього не застосовується пропорційний сценарій R-001, пропустити це місце та продовжити перевірку нижчих позицій.
8. Якщо після повного обходу не знайдено фізично й економічно доступної дії, повернути `no_action_required`.

## Вкладник гільдії, якого можна обійти

1. Знайти першого вкладника гільдії, якого можна обійти.
2. Перевірити наступні місця поспіль, доки їх займають вкладники гільдії, яких також можна обійти.
3. Цільовим вибрати останнього проблемного вкладника цієї безперервної групи.
4. Обчислити мінімальний внесок власника за R-004 відносно цільового вкладника.
5. Не включати до суми гарант наступного вільного місця або іншої групи.
6. Повернути `guild_member_can_be_overtaken`, номер місця останнього вкладника групи та дію власника.
7. Після фактичного внеску виконати новий повний розрахунок.

## Вкладник гільдії не доплатив вартість місця

1. Не створювати порожнє місце лише через те, що співгільдієць вклав менше його вартості; зберегти його фактичну рейтингову позицію та не зсувати нижчих співгільдійців.
2. Під час обходу місць після пропуску неперебивних сторонніх позицій перевіряти вкладників гільдії суворо згори вниз.
3. Якщо внесок вкладника менший за вартість його місця, зупинити пошук.
4. Обчислити різницю між вартістю місця та фактичним внеском.
5. Якщо різниця не перевищує залишок, рекомендувати повну доплату.
6. Якщо різниця більша за залишок, зарезервувати власнику `1 СО` і рекомендувати вкладнику `max(0, remainingFp − 1)`.
7. Повернути `guild_member_below_place_cost` і дію `guild_member_top_up`, адресовану конкретному вкладнику; окремо вказати повну та невідновну недоплату.
8. Не розраховувати гарант або доплату нижчих місць до фактичного внеску й нового сканування.

## Вільне місце потребує гаранту власника

1. Після пропуску неперебивних сторонніх позицій знайти найвище вільне місце.
2. Знайти найближчого нижнього стороннього вкладника або використати нуль.
3. Обчислити внесок власника за R-006.
4. Якщо внесок більший за нуль, повернути `empty_requires_owner_guarantee` та дію `owner_deposit`.
5. Не рекомендувати учаснику гільдії заходити на місце до внеску власника.
6. Після внеску власника виконати новий розрахунок; якщо гарант більше не потрібен, повернути `empty_guaranteed` із повною вартістю місця.
